## 2. What shipped in this session

All of it is in `CHANGELOG.md` under `[Unreleased]`; the bullets below are the
ones a reader needs to find quickly.

**The install command the site printed was rejected by the CLI a reader
installs.** `npx --yes litespm@latest` resolves to npm's `latest` — **0.4.1**
— and the site appended `--agent` and `--all-detected` to it, which that
release's `install` verb does not take. Reproduced in a clean sandbox:
`Install error: unknown flag "--agent"`. The target is now spelled `--host`
(accepted by 0.4.1 *and* by this tree, whose help calls it the older spelling
of `--agent`), an untargeted command stays bare, and the entry page explains
what a release that stops to ask is asking for.

**Nothing checked the published package — the root cause.** The gate that
compares the site's flags to a CLI read `cmd/litespm/main.go`: source nobody
can `npm install`, so it could only ever disagree with the binary a reader
runs. `web/scripts/check-install-command.mjs` now parses `parseInstallFlags`
out of the *published version's git tag*, takes that version from npm's
`latest` (committed snapshot offline), fails when the two disagree, and
refuses any flag the published binary lacks. The snapshot is
`web/data/published-cli.json`.

**The site's per-host remote verdicts came from a second, hand-written
table** (`REMOTE_TRANSPORTS`, 8 rows) that fell behind the re-verified
registry (46 hosts) — so 38 hosts read "unknown" where the binary would
install. `scripts/gen_hosts_ts.go` now emits the registry's own
`RemoteEntrySpec.Transports` as `remoteTransports`, the module reads it, and
the table is deleted. The drift guard that caught this was satisfied by
removing the second source, not by extending it.

**Truthfulness:** "update" was promised for all three kinds everywhere (only
`litespm skills update` exists); the product was positioned five ways in one
page's metadata; `/how-it-works` said the catalog was *signed* when the
pointer is digest-verified; `/security/` claimed no upstream publishes star
counts (GitHub repositories do).

**Branding:** `public/og.png` read "LiteSPM Market" — a name no page uses —
and there was no `apple-touch-icon`, so iOS put a page screenshot on the home
screen. Both are now generated by `npm run gen:og` from the same constants,
palette and vendored IBM Plex as the page, the card carries the title it was
drawn from as a PNG `iTXt` field, and `scripts/check-og-image.mjs` (in
`npm run lint`) compares that field back against `lib/site.ts`. The favicon,
the touch icon, the card and the header are one mark now.

**Accessibility:** `AgentLogo` and `PublisherMark` hard-coded `bg-white` while
their ink followed the theme — **1.57:1** on 62 tiles measured on the live
site. The plate and its ink are tokens (`--logo-plate`,
`--logo-plate-ink`), the contrast gate holds the pair in all three themes,
and the gate now fails on any background literal a palette-based check cannot
see.

**The entry page's tab title was a coin toss.** The edge Worker writes the
entry's `<title>` into the served HTML; React re-applies the route's generic
title when the shell commits, and whichever landed last won. The head is
reconciled by an observer now (title + one `og:title` + one
`rel=canonical`), and the Worker's inline row is read *after* the mount, so
React stops discarding and rebuilding the whole tree (error #418) — which was
also a browser-suite failure.

**CI:** the product-link gate ran *before* the export existed, so the check
that exists to stop a link naming a product the catalog does not have was
never running on a bundle. It is a step after the build now, and it skips
loudly when there is no export. **Go:** `writeBoundedFile` removed the file
it had just written while its handle was open, which Windows refuses — a
truncated entry survived on disk as an empty file (this was the Windows-only
CI failure).

**Site content:** the sitemap omitted the five decision pages; five pages
ended on a legend or footnote with nothing to do; the homepage taught two
different step models (five, then three); four comments stated the opposite of
the product.

## 4. What is failing, precisely

`npx playwright test` → **210 passed, 2 failed** at handover.

1. **`tests/budgets.spec.ts:61` — CLS on `/` = 0.01177 against a 0.01
   budget. Real, and caused by this session's home-page copy (the hero's
   "of 69,376 entries" line and the product card's 5→3 captions).**

   `PackageIndexShell`'s `min-h-[44px]` note slot is this repo's own pattern

   currentRect / element` for every shift:

   ```js
   new PerformanceObserver((list) => { for (const e of list.getEntries()) {
     for (const s of e.sources || []) console.log(e.value, s.node?.id, s.previousRect, s.currentRect);
   }}).observe({ type: "layout-shift", buffered: true });
   ```

   Tracked as **TODO LPSM-J016**.

## 6. Facts that will bite you if you do not know them

- **The published CLI and this tree are different programs.** `npm`'s
  `latest` is 0.4.1, the newest GitHub release is `v0.4.1` (17 assets), and
  the tree is 0.6.0 with no release. `STATUS.md` §6 "The site, and the CLI a
  reader actually installs" is the short version of this.
- **A stale `pages-dist/`** at the repository root (gitignored) is a *local*
  deploy artifact and may predate the current branding — it still says
  "LiteSPM Market". `scripts/deploy-pages.sh` regenerates it; never deploy a
  copy that is standing around.
- **`npm run lint` takes ~7 minutes** because it rebuilds the search index
  (99,482 tokens) and recomputes publisher counts. That is deliberate.
- **Playwright's server is Miniflare on port 8788** (`web/tests/serve.mjs`).
  A stray one holds the port and the suite dies with `ERR_ADDRESS_IN_USE`;
  `ss -lptn 'sport = :8788'` then kill by pid. Do **not** `pkill -f
  serve.mjs` from a shell whose own command line contains that string.
- **`ResolvePlatformPaths()` reads `$HOME`**, so `t.Setenv("HOME", …)` does
  not isolate the data root in tests — set `LITESPM_DATA_ROOT`.
- **The Go error families are `LPSM-RESOLVE` and `LPSM-INSTALL`**, spelled
  the way the codes already were (three constructors used `LPSM-RESOLVER` /
  `LPSM_RESOLVE` before this session).
- **`.slim/deepwork/` is gitignored.** Notes that must survive a machine move
  belong in `docs/` or in `STATUS.md` / `TODO.md`.

## 8. Postscript, written later the same day — 0.6.0 shipped

Everything in §5's **J017** happened, and the way it happened is worth
recording because it is a trap for the next release:

1. `npm publish` was run from `npm/` and npm started serving `litespm@latest`
   = **0.6.0** within minutes.
2. The npm package's `postinstall` downloads its binary from the
   **`v<version>` GitHub release**, and no `v0.6.0` release existed — so
   `npm install litespm@latest` failed outright with `HTTP 404`, which is
   *worse* than the wrong-flag failure it replaced. Verified in a clean
   sandbox before anything else was done.
3. `gh variable set ALLOW_NPM_SKIP=true`, then `git tag -a v0.6.0 && git push
   origin v0.6.0`. The release workflow builds six binaries, signs them with
   cosign keyless, generates the SBOM, publishes the GitHub release, runs the
   npm wrapper tests **against the real assets** (the three that skip on a
   machine with no release), and — because the variable is set — prints a
   warning and skips the duplicate `npm publish` rather than failing the job.
4. `web/data/published-cli.json` was updated from the tag, and the gate now
   reports the published CLI as 0.6.0. The site keeps `--host`: it is the
   spelling every release takes, so a reader who pinned 0.4.1 still succeeds,
   and switching to `--agent` would buy nothing.

**For the next release:** npm and the GitHub release have to be published
together. Either let `release.yml` do both (set the `NPM_TOKEN` secret and
clear `ALLOW_NPM_SKIP`), or publish npm yourself and leave
`ALLOW_NPM_SKIP=true` in place — an npm tarball with no matching release
assets makes `npx litespm@latest` uninstallable for everyone.

facts; this file carries the story.
